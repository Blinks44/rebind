# Multi-vendor input batteries

Reviewed 2026-10-16 for [DEVICE-003](../tasks/DEVICE-003-multi-vendor-battery.md), baseline `1a0801b`. Scope is input-device inventory and battery reads, not DPI/RGB/remapping adapters for other brands. A profile or passing mock is not a hardware compatibility claim.

## Selected native paths

- Public IOKit enumerates all external mouse/keyboard/touchpad HID collections. `IOHIDManagerOptions.independentDevices` prevents a discovery match from opening/scheduling unrelated vendor interfaces. Built-in devices, consumer-only/headset and vendor-only collections do not become input cards. Zero location IDs fall back to the registry entry ID so unrelated Bluetooth devices do not merge.
- A driver-provided `BatteryPercent` is read only below a known input's registry service. The older Apple device-management source remains a fallback. Standard [Generic Device Controls / Battery Strength](https://developer.apple.com/documentation/hiddriverkit/hid-usage-tables) elements (page 06, usage 20) are read with public IOKit and normalized by their declared logical range. No key elements or raw keyboard reports are read. Invalid/out-of-range values and uninitialized cached input values remain unknown.
- Public [CoreBluetooth connected-peripheral retrieval](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/retrieveconnectedperipherals(withservices:)) selects already-connected HID-service peripherals (1812); there is no radio scan or pairing flow. Only static Report Map (2A4B) is read first. A bounded USB HID short-item parser must identify a mouse, keyboard or touchpad Application Collection before Battery Level (2A19, service 180F) is read. Consumer-only maps/gamepads do not qualify. [Bluetooth SIG assigned numbers](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Assigned_Numbers/out/en/index-en.html), [Battery Service](https://www.bluetooth.com/specifications/specs/battery-service/), [USB HID specifications](https://usb.org/hid).
- Bluetooth access is explicit from Devices until this app has been authorized. Denial opens the Bluetooth privacy pane; restriction disables the request control. The purpose string and UI are translated into six languages. No grant is assumed or changed in tooling. Delegate work runs on the main queue; reads have a five-second deadline. [Cancelling a peripheral connection](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager/cancelperipheralconnection(_:)) releases only Rebind's logical GATT connection, leaving other clients' connections intact. A pending disconnect prevents an old cancellation callback from closing a new read.
- USB battery work runs on separate utility queues, one in-flight read per location; disconnect/interface changes invalidate late results. Native synchronous IOKit feature calls use the OS's own I/O completion/timeout, so this is not a measured hard deadline for device IPC. They never block the UI/event tap or queue repeated reads behind a silent endpoint. Logitech remains the preferred source for its devices; ambiguous Bluetooth names are not attributed to one of two identical inputs.

## Compatibility limits

General HID/macOS/BAS support is vendor-independent only where the hardware/driver exposes those standards. A branded 2.4 GHz receiver can still require a proprietary protocol. Known Razer/SteelSeries USB profiles are implemented, not locally hardware-verified. Razer proprietary BLE, Corsair-specific USB, other private receiver protocols, exact charging state from generic BAS, and multiple BAS battery instances are not claimed. Denied access or missing/inaccessible services produces no invented percentage. New vendor hardware requires a read-only named-model/transport probe and reconnect/sleep checks before its capability can be promoted.
