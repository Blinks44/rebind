## Selected protocol boundary

Experimental support requires an input-device classification, HID++ RGB Effects 0x8071 and a complete bounded inventory advertising static RGB in every zone. Monochrome-only inventories are excluded. Use each zone's advertised effect ordinals; only volatile full-power writes are allowed. Brightness 0x8040 is independent: absent/malformed brightness must not hide a compatible color engine. Advertised step counts select halving levels; exact write/readback remains required. Firmware differences become named-model adjustments rather than silently accepting a wrong value.

Separate illumination is used only when advertised. Without brightness, an off switch requires Disabled in every zone. Blinking requires Breathing in every zone; battery policy also requires readable native power modes, so refresh cannot wake an idle device. G915 keeps its measured range/step admission. Older 0x8070, per-key-only protocols and other brands remain outside this implementation; unsupported devices receive no guessed commands.

## Connected G915 timing observation

On the existing receiver/slot, temporary native dim=5 s/off=15 s reached PowerSave at the 6 s sample and PowerOff at the 20 s sample. With dim=5 s/off=0, PowerOff appeared at the 6 s sample: zero is not Never. Restore/readback confirmed flags 0, dim 120 s, off 300 s, brightness 50 and firmware control/events 0. Sampling uses a temporary diagnostic only, not app input monitoring or a production timer. Physical Shift wake, exact preset mapping across reconnect and genuine Never semantics remain acceptance gates. Build 28 later exposed the presets; the October 28 report below supersedes logical PowerOff as evidence of visible off.


## G915 software-color idle-off correction — 2026-10-28

The tester observes white lighting after native mode 3; a temporary explicit power-control lease and full→off→full command sequence visibly switches it off. Native timeout readback does not verify actual LED output. [OpenLogi 0x8071 wire reference](https://openlogi.org/hidpp/features/x8071-rgb-effects) confirms timeout/activity event bits 4/2 and power-control bit 2. [Solaar's RGB power manager](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/rgb_power.py) uses native events with explicit power modes; its GPL source is not copied. This refresh does not add a dependency or invalidate the preceding library/license audit.

Decision: retain native inactivity detection and the existing MIT HIDPP/IOKit transport; explicitly drive PowerOff/FullRGB from device notifications while a G915 timer preset is active. Alternate idle/activity subscriptions, preserve unrelated flags, guard companion ownership and serialize I/O. No host input monitor, periodic polling, typed content, EEPROM or profile changes. A standalone diagnostic received native idle/active events and acknowledged transitions; full installed off/wake/reconnect acceptance remains in [LIGHT-001](../tasks/LIGHT-001-keyboard-lighting.md#installed-idle-off-failure-and-event-driven-fix--2026-10-28).
