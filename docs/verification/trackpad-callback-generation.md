# Trackpad callback generations — 2026-10-12

[INPUT-001](../tasks/INPUT-001-four-finger-tap.md); SPEC §§3.4, 6, 12, T1/T2. Engineering-only repair to the existing native buffer; no UI, Sketch, gesture thresholds, schema, dependencies or capability expansion.

## Defect and correction

Callback admission and publication use separate short buffer critical sections. Previously a callback could pass the initial accepting check, copy its native frame while capture stopped/restarted or overflow cleared the queue, then append to the recovered queue. A Boolean accepting check did not distinguish these generations. Even with unchanged runtime revision/activity, an obsolete release/contact could contaminate recognition; if the new queue was full, the obsolete callback could clear all its fresh frames.

The buffer now captures its generation at admission. Every queue clear advances that generation, including stop/start, an accepting reset and overflow. Publication checks both acceptance and generation under the existing mutex before checking capacity. Obsolete copies cannot enter or overflow the current queue. Existing overflow acknowledgement/quarantine and session/worker guards remain.

Native memory reads remain outside the locks; no native pointers escape and no callback Task/actor hop, I/O, diagnostic logging or additional contact allocation was added. Capacity/drain budget remains 64 frames. Retained the existing synchronous [Swift Mutex](https://developer.apple.com/documentation/synchronization/mutex) and [withLock](https://docs.swift.org/latest/documentation/synchronization/mutex/withlock(_:)/), reviewed 2026-10-12. This changes queue admission, not the private acquisition mechanism; no library or copied third-party implementation was needed.

This guard covers callbacks admitted before invalidation. It does not establish private-framework callback quiescence or identify an old native callback that first enters Swift after capture has restarted. Posting remains a separate guarded operation; controlled loss/restart timing, native callback scheduling and end-to-end latency remain unverified.
