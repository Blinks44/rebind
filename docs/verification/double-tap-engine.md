## Implemented behavior and limits

Schema **26** adds separate three/four-finger double triggers, preserving single identities, manual profiles, preferences, pause and atomic configuration transactions. Historical schemas 1–25 reject a new double payload, including inactive profiles. Binding validation retains unmodified press-only shortcut output. Distinct display labels exist in EN/RU/DE/FR; current editor still creates only four-finger single taps; the saved/released UI-013 design is ready for native adoption.

Consumer sequencing retains a preliminary qualified release so a fast second contact can start before the first 60 ms settling window completes. No action is eligible until settling after the final release. Input activity cancels the entire sequence, including delayed singles. A same-count nearby pair produces one double and consumes its second tap. With no double rule, singles retain their short settling path. A lone tap waits until its configured pair deadline only when its double rule is enabled; double-only rules have no single fallback.

Pair start must precede the first release's deadline; a valid second contact may finish after it. Receipt and poll clocks remain separate and monotonic. Native classification keeps the existing 400 ms duration, placement/lift/travel and two-peak-frame limits; the separate receipt-duration bound is 500 ms to accommodate the existing 100 ms acquisition/dequeue skew, without broadening native qualification. Starting centroid is retained transiently for the existing provisional 0.08 normalized proximity test, never persisted or reported.

The native adapter conservatively discards an older single when a new contact starts at/after its deadline, or when a different-count/distant tap ends a pair. It can retain the new qualified tap for its own rule; it does not queue/replay two old actions. This is narrower than the pure sequence's general fallback array contract and prevents output into an active/mismatched gesture. Movement, held/invalid/unknown contacts, stale/future/malformed/lost frames, input activity, focus/revision/profile changes, protected sessions, producer stop, overflow and late polls cancel. Trailing untimed zero frames preserve an already qualified tap; untimed nonzero contacts fail closed.

Dispatch remains one bounded mailbox slot with no retry/global fallback. The final worker rechecks focus/PID, revision/activity, held input, permission/protected state and expiry. Callback acquisition, physical-device scope, synthetic tags, sender and real configuration are preserved. Native two-finger double taps, physical clicks, corners, modifiers and broader actions are still unwired.
