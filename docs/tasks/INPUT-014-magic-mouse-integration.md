## Implemented scope

Experimental stationary one/two-finger single-tap candidates now have their own Magic Mouse category, complete gesture selector, optional single held Command/Option/Control/Shift, per-app rules, profile persistence and shared one-shot action catalog/output recorder. Basic tap action delivery is user-confirmed on 2026-10-19; native-double coexistence has a reported conflict below. Three/four-finger gestures, swipes, holds and native-double replacement remain research-gated; this testing pool does not reduce broader release gates.

- `NativeTrackpadDevice` shares the existing isolated private observer with a separate family-112 portrait surface adapter/buffer. Only the first matching connected mouse is acquired; no physical-device rule selector/routing. IOKit registry-entry identity distinguishes a live connection from its temporary discovery wrappers; a removed/replaced connection resets the session. Created-list ownership is balanced when reusing an adapter; retired callback contexts stay alive until process exit because callback quiescence is undocumented.
- Callback registration now returns **Void**, with actual start/stop status checked. This repairs the app's earlier Boolean ABI declaration for all touch surfaces; it needs a physical trackpad regression check separately from the user's unchanged older artifact. OS major gate remains 26/27; no root, new permission or OS preference mutation.
- Ordered 64-frame buffering/generation/loss guards are reused. Mouse frames never feed either trackpad click filter. The shared short-contact recognizer keeps the original trackpad defaults; the mouse path uses 20–200 ms native duration, at least two peak frames/20 ms peak, 0.025 per-contact normalized travel, identity/placement/lift/continuity checks and an independent 20–300 ms receipt-duration bound.
- Known neutral and the existing three-second capture arming gate precede recognition. Release settles for 60 ms, with 100 ms maximum lateness. Invalid/stale/gapped frames, queue overflow, activity/focus/revision changes and stopped capture cancel instead of delivering a backlog. Fresh neutral observations rearm the next stroke.
- A separate raw activity counter sees real buttons/keys/scroll and pointer movement; mouse-only tap rules also enable the native pointer-motion subscription. It remains independent even when the trackpad path classifies a native tap-made click as part of its own gesture. Held buttons block recognition. The shared bounded touch-output slot and worker retain PID/activity/revision/expiry checks and tagged balanced shortcuts; mouse output does not pollute opt-in trackpad diagnostics.
- Ordinary clicks/scroll/native gestures are never suppressed. Repeated single taps may also invoke native one-finger Smart Zoom or two-finger Mission Control; the editor explains the manual setting change. Mouse movement cancels even if surface contacts stay stationary. No idle polling when no relevant rules exist; configuration/status/foreground changes wake capture, quiet buffers wake on a frame, with a two-second discovery deadline while observing a configured mouse.
- Schema **42** adds the scope/trigger, rejects their presence in older schema files, and preserves existing categories/configuration. The pre-existing name-migration test now expects `Configuration.currentSchemaVersion` rather than a hard-coded 41; corrupt/future-file protection is unchanged.

## Magic Trackpad discovery regression — 2026-10-19

Following the latest bundle handoff, the user reports that Magic Trackpad three/four-finger taps no longer work while clicks do. The exact running artifact was not independently inspected. Review isolated a regression introduced by the Magic Mouse acquisition change: the shared adapter compared both native device ID and object address when rescanning. `MTDeviceCreateList` creates fresh wrappers for the same connected trackpad, so the two-second scan retired the observer/session repeatedly. The three-second tap arming gate could never finish, while the click path continued receiving fresh contacts. This is separate from the corrected output-slot ownership finding above.

Agent evidence on macOS 27.0.1: three read-only enumeration passes found the same external trackpad/native ID with a different object each time. `MTDeviceGetService` plus public `IORegistryEntryGetRegistryEntryID` returned the same registry entry across those wrappers. No actual identifier was logged. A temporary test of the real `NativeTrackpadDevice.acquire` path failed before correction in all three repeated discoveries (adapter and buffer identity: six assertion failures); it registered callback contexts but never called start, read contacts/configuration or posted input.

Correction: retain/reuse the adapter by its service registry-entry identity, independent of wrapper address. The connection value compares registry IDs; missing/failed identity rejects acquisition, and a different registry entry selects a new adapter. Existing absent-device retirement and process-lifetime callback safety remain. No gesture threshold, three-second arming, single/double timing, click suppression, shared-slot fix or rule migration changed. Native pointer identity is no longer treated as a connection identity.

## Magic Mouse native-double conflict — 2026-10-19

The user reports that Magic Mouse tap actions work well, but a two-finger double tap invokes the configured single-tap action before native Mission Control. Exact mouse model/transport, running artifact, active rule/action/modifier and measured timing were not supplied. This confirms basic app action delivery in the reported walkthrough, not every preset/action or the broader safety/reconnect matrix.

Source review explains the conflict: `MagicMouseTapSession` submits each qualified single after `TrackpadTapGate`'s 60 ms release settling. There is no native-double arbitration; a later contact cancels only output still pending. The second stroke may qualify another single too. The editor already discloses native gesture coexistence. Apple's [gesture guide](https://support.apple.com/en-us/102482), rechecked on this date, identifies two-finger double tap as Mission Control and one-finger double tap as Smart Zoom. Apple's public [doubleClickInterval](https://developer.apple.com/documentation/appkit/nsevent/doubleclickinterval) is a click interval; no verified equivalence to the native Magic Mouse tap threshold was established.

Decision, 2026-10-19: preserve fast singles with the existing 60 ms release settling; do not add native-double arbitration. The user prefers manually disabling the overlapping macOS gesture or assigning the desired action elsewhere. Rebind can assign Mission Control to an available supported trigger; this does not mean the native double tap itself can be rebound in Rebind's current single-tap-only mouse pool. The editor already explains manual native-gesture disabling. Delaying every single through a double-tap window was considered and rejected for responsiveness; no general impossibility of native suppression is claimed. No timing, app code, system setting, actual rule or artifact changed; no tests/build were rerun. Documentation links/whitespace and `git diff --check` pass. Next: verify named one/two-finger attempts with the overlapping native gesture disabled, including ordinary input/false positives and reconnect. Broader acceptance below stays open.

## Controller lifecycle and dormant wake-up — 2026-10-19

Code review found a dormant-capture recovery gap: `poll` sets its timer to a distant deadline when `canDispatch` becomes false (editing, recording, exclusion, pause/suspension). The model previously woke it only for configuration or tap-status changes, while editing/recording can end with the tap still active. Foreground activation often masks this gap; this was a source finding, not a newly reported hardware failure.

`AppModel.refresh` now checks the capture control revision/admission. Only a changed revision or admission wakes the controller; unchanged UI refresh never restarts discovery or adds surface polling. The existing model refresh bounds this check to its normal cadence. Recognition thresholds, 60 ms fast-single settling, three-second arming, native gesture policy, callback work and shared adapter stay unchanged.

The controller now has an injected main-actor observer boundary and clock, and the native environment sampling is separate from a bounded service pass. Production uses the same `NativeTrackpadDevice`; tests supply an in-memory buffer/observer and do not read physical contacts or post input. New controller cases cover both presets with exact modifiers, stable discovery without restart, once-only output, disconnect cancellation and fresh replacement arming, edit/record/exclusion/pause/suspend recovery, permission/stop cleanup preserving the trackpad-owned slot, and failed-observer replacement. A failed connection still latches until reconnect/reopen, as the existing help says.
