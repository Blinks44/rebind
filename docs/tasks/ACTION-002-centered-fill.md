The strip maximum-frame component depends on a pile maximum-frame component and layout inputs, rather than merely a rendered card edge. This follow-up still does not establish a complete safe portable computation. ## Formula research after fixed-policy implementation

Refreshed web/GitHub searches did not establish a published Apple sizing formula or ready-made adapter. Additional read-only private-framework diagnostic defaults: left-strip inter-item horizontal spacing 16, pile vertical spacing 30, preferred/absolute minimum item heights 96/20, generic horizontal spacing 32 and inline-App-Exposé pile horizontal spacing 48. Temporary reflection analysis identified maximum-strip and maximum-pile-frame components and their dependency on layout state. The known non-hidden reserve remains `floor(stripMaximumFrame.width * 0.66) + leftStripEdgeHorizontalInset + horizontalInsetFromStrip`; defaults for the last two terms are 16 each. The hidden-strip branch uses the 4 pt minimum instead. This is partial macOS 27.2 static evidence, not a complete or portable Apple contract; no inferred width or private call enters Rebind. Inspected WindowManager executable SHA-256: `35f57fc7fb20241747fba5271aec0bccc2fd3ea981a418ce3596d63cec40418b`.

Targeted web follow-up (2026-11-06): BetterTouchTool author Andreas Hegenberg [reports on 2022-11-10](https://community.folivora.ai/t/stage-manager-snap-earlier-leave-gap-option-in-btt-on-the-right-side-when-dock-is-on-the-left/28909) that BTT reserves the maximum Stage Manager size, approximately 10% of display width, including ultrawide cases; he [repeats the approximation on 2022-11-22](https://community.folivora.ai/t/center-window-action-offset-with-stage-manager/29219). This is a useful maintainer observation from Ventura, not an exact current Apple formula: 10% of the observed 2560 pt display is 256 pt, not 244. The [Stage Manager Options investigation](https://gist.github.com/ejkarne/c73028e447d716b02063b0870c12c6be) documents private spacing/size keys and explicitly uncertain effects, without a full formula. [Rectangle maintainer documentation](https://github.com/rxhanson/Rectangle/blob/main/TerminalCommands.md#adjust-macos-ventura-stage-manager-size) instead uses a configurable 190 pt default or screen-width proportion. These sources provide leads, not a validated replacement for fixed 244 pt; no app changes or new package from this follow-up. Documentation diff check passes.

Next research step: establish the maximum-pile/strip-width inputs against observed native stage frames across display scales and strip hidden/grouping states before proposing automatic adaptation. Keep the authorized calibrated policy until that mechanism is reliable. Native installed verification can proceed independently on the current package.
