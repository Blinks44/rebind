## 2026-10-24: Input-tap crash after long scrolling

Installed builds 11 and 14 crashed three times (October 22–24) with `EXC_BAD_ACCESS` in the `Rebind input tap` thread: its 544 KB stack was exhausted inside `EngineMailbox.noteScroll()` → pointer-app tracker. Cause: the scroll observer was a bare closure stored as a `Mutex` value; Swift reabstracts the `inout` value for the generic `withLock` and writes it back, so each wheel click that may glide wrapped the stored closure in one more thunk until calling it overflowed the stack. A standalone `-O` reproduction crashed at 200,000 calls; the struct-wrapped form did not. Both `EngineMailbox.scrollObserver` and the identical `HIDReportDevice` notification handler now keep the closure in a struct field; disassembly of build 15 shows no write-back. Other locked closures live inside state structs and were unaffected.

A new test calls `noteScroll()` one million times; with the old mailbox the test process crashed, with the fix it passes. `dev.sh test` passed 912 tests in 143 suites. `release.sh` passed signing, strict signature and image verification. Artifact **1.0.0 (15)**: `apps/rebind/build/release/Rebind-1.0.0-15.dmg`; SHA-256 `e8696d83571bf8fdd97ff48c5cf37aafb5f83e26815370075b79778a3261daa9` (`SHA256SUMS.txt` regenerated). No installation or publication. Next: install build 15 and scroll for a long session with smooth scrolling on.
